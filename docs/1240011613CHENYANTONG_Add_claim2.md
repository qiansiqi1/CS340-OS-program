## Claim 2: ASan Performance Overhead Reproduction

Experiment Objective

This experiment reproduces the runtime performance overhead introduced by AddressSanitizer (ASan), as evaluated in the original paper AddressSanitizer: A Fast Address Sanity Checker.

The goal is to quantitatively compare the execution time between:

• Native optimized program (without ASan instrumentation)

• ASan-instrumented program (with runtime memory checking enabled)

By measuring real execution time across multiple trials, this experiment verifies the performance slowdown caused by ASan’s memory instrumentation and runtime checks.

Experiment Environment & Configuration

• Compiler: clang-18

• Optimization level: -O2 (consistent with the paper’s evaluation)

• Operating environment: GitHub Actions Ubuntu 24.04 virtual machine

• Benchmark program: perf_bench/perf_micro.c

• Test workload: intensive repeated malloc / free operations with memory write access

• Number of trials: 5 repeated runs

• Automation: fully automated build & test via scripts/run_perf.sh and GitHub Actions CI
Limitation Note
GitHub Actions uses shared cloud virtual machines with unstable CPU scheduling. The measured results contain unavoidable system noise and can only verify workflow reproducibility, not precise physical-machine performance.

Comparison with Original Paper

The original ASan paper reports an average performance overhead of 1.73× (73% slowdown) for general SPEC CPU2006 benchmarks.

In this experiment:

1. The benchmark focuses purely on frequent malloc/free operations, which are known to be heavily instrumented by ASan. Memory-heavy workloads naturally produce larger overhead than average SPEC programs.

2. GitHub Actions virtual machine scheduling noise further increases runtime variance and overall slowdown.

3. Modern clang-18 ASan implementation differs slightly from the 2012 original version, leading to minor behavioral differences.

Therefore, the measured overhead is reasonable and consistent with the paper’s qualitative conclusion:
AddressSanitizer introduces moderate but non-negligible runtime overhead for memory-intensive programs.

This part successfully builds a fully automated performance benchmark pipeline on GitHub Actions.
